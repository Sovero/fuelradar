## Что должно заработать

Три критических сценария брифа запускаются в Chromium одной командой и не требуют
реальных карт, Telegram/VAPID или внешней сети. При падении сохраняются trace и
screenshot, обычный успешный прогон не оставляет шумных артефактов.

## Из брифа, дословно

> «E2E — Критические пользовательские сценарии»
> «Пользователь открывает FuelRadar … выбирает AI-95 … видит статус и confidence … запускает маршрут»
> «AI95 отсутствует … нажимает “Следить” … получает push»
> «Нажимает “Сообщить” … GPS подтверждает … Observation сохраняется … Confidence пересчитывается»

## Критерии приёмки

- [x] Playwright Chromium проходит поиск/геолокация/фильтр/карточка/маршрут

- [x] API и карта стабилизированы локальными mocks/fixtures, внешняя сеть и секреты не нужны
- [x] Trace/screenshot только при сбое; селекторы основаны на ролях/доступных именах
- [x] `npm run test:e2e` документирован; существующие vitest/typecheck/build остаются зелёными

## Итог (2026-09-13)

5 E2E-тестов в Chromium, запуск `npm run test:e2e` (или `make e2e`), ~10 с:
- home-screen — smoke с нулём ошибок консоли: карта инициализировалась, realtime жив, фильтр АИ-95 → URL, карточки списка со статусом+confidence;
- route-mode — «Коридор маршрута»: 2 клика по карте → запрос коридора;
- watch-and-notify — фильтр «АИ-95 + Нет» → EmptyState → «Следить» → правило создано → событие в ленте уведомлений;
- report-gps (2 теста) — гость получает приглашение на вход; с профилем форма открывается, GPS рядом (<300 м), отчёт принят, экран успеха.

API и внешняя сеть (тайлы, глифы) — локальные моки на уровне страницы; service worker в E2E отключён (его запросы не перехватываются page.route). Trace/screenshot — только при падении; селекторы — роли/доступные имена. Системный Chrome как Chromium-канал — см. concerns в state.json.
