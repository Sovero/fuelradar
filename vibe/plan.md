## Шаги

### Шаг 1: 2ГИС в buildRouteUrl

- **Что:** в `frontend/lib/format.ts::buildRouteUrl` добавить провайдер
  `"2gis"`; тип провайдера расширить (`"yandex" | "google" | "2gis"`).
- **Критерий выполненности:** `buildRouteUrl(45.03, 38.97, "2gis")` возвращает
  URL на `2gis.ru` с корректными координатами.
- **Файлы:** `frontend/lib/format.ts`
- **Тесты шага:** `frontend/lib/format.test.ts` — 2ГИС deep-link (координаты в URL),
  плюс регресс: яндекс и google не сломались.
- [ ] Выполнено

### Шаг 2: хук навигационного предпочтения

- **Что:** новый `frontend/lib/hooks/useNavigationPreference.ts` — возвращает
  `{ provider, setProvider }`; localStorage-ключ `fuelradar:nav-provider`,
  валидация значения из хранилища (чужое/битое → дефолт `"yandex"`).
- **Критерий выполненности:** setProvider сохраняет; при новом монтировании
  читается сохранённое; невалидное значение отбрасывается к дефолту.
- **Файлы:** `frontend/lib/hooks/useNavigationPreference.ts` (новый)
- **Тесты шага:** `frontend/lib/hooks/useNavigationPreference.test.tsx` —
  сохранение, чтение, битое значение → дефолт.
- [ ] Выполнено

### Шаг 3: UI выбора в карточке станции

- **Что:** в `frontend/components/station/NavigationPreference.tsx` (новый) —
  сегмент-контрол из трёх кнопок (Яндекс / 2ГИС / Google) рядом с действиями
  карточки; выбранный вариант подсвечен; подпись со скринридер-именем.
  Интеграция в `StationCard.tsx`: кнопка «Маршрут» (fallback-ветка `<a>`)
  открывает `buildRouteUrl(lat, lon, provider)` от хука. Ветка внутренней
  карты (`onBuildRoute`) не меняется.
- **Критерий выполненности:** в карточке виден выбор из трёх навигаторов,
  клик сохраняет выбор, «Маршрут» открывает выбранного провайдера.
- **Файлы:** `frontend/components/station/NavigationPreference.tsx` (новый),
  `frontend/components/station/StationCard.tsx`, `frontend/lib/i18n.ts` (ru+en)
- **Тесты шага:** `frontend/components/station/NavigationPreference.test.tsx` —
  рендер трёх вариантов, выбор, aria-метки; i18n-тест обоих словарей.
- [ ] Выполнено

- [ ] Выполнено

## Порядок и параллелизация (шаги 4–5 пайплайна)

Задача весит меньше одного хода агента (три маленьких файла, один
интегрируемый): шаги строго последовательны и имеют общие файлы (i18n.ts,
StationCard.tsx). Оценка по пайплайну: **один исполнитель, без worktree** —
параллель с оркестратором здесь усложнил бы мердж без выигрыша во времени.
Это решение зафиксировано сознательно, а не «просто сделали сами».

| Подзадача | Шаги | Worktree/ветка | Воркер | Валидация оркестратора |
|-----------|------|----------------|--------|------------------------|
| — (не применимо) | 1–4 | main | один агент | тесты + typecheck + живая проверка |
