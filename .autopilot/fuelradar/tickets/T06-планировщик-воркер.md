# 06 — Планировщик и воркер сбора

**Требования:** R53, R54, R55, R56, R57, R70, R83, R84
**Blocked by:** 02, 04
**Зона:** `backend/app/worker/`
**Волна:** 5
**Status:** ready

## Что должно заработать

Фоновый воркер (APScheduler, отдельный процесс — compose-сервис `worker`): регулярный
сбор по расписанию (базово 60 мин), очередь приоритетов P1–P4 (активные правила
пользователей → избранные АЗС → зоны пользователя → остальной мастер-каталог),
настраиваемые интервалы (обычный 60, избранное 30, дефицит 15–30, стабильное 120 мин)
с жёстким потолком rate limit источника (R54/R55). Сбои: backoff, изоляция, данные не
удаляются (R56/R84). Ручной refresh по заданию из T05. Рестарт безопасен: lock на задание,
догоняющий прогон без дублей. Метрики сбора (запросы/ошибки по источникам, длительность) —
R70. Сбор никогда не запускается синхронно из API (R83).

## Из брифа, дословно

> «Scheduler… Базовое значение: 60 минут»
> «P1 — активное пользовательское правило, P2 — избранные АЗС, P3 — зона пользователя, P4 — остальной мастер-каталог»
> «данные не удалять; статус не превращать в NO FUEL; снизить freshness; записать ошибку; повторить запрос позже»
> «Сбор внешних данных никогда не должен выполняться синхронно при открытии карты»

## Разделы спецификации

Истории §12 №1–12, §9 №2/4, §6 №4/5, §17 №2.

## Критерии приёмки

- [ ] Расписание запускает сбор каталога и (при данных) наблюдений; интервалы из конфига
- [ ] Очередь приоритетов соблюдает P1 > P2 > P3 > P4; частота по категориям (30/60/120)
- [ ] Адаптер не опрашивается чаще своего min_interval (rate limit)
- [ ] Сбой источника: backoff, ошибка в collection_logs, остальные задания идут, данные не тронуты
- [ ] `POST /admin/sources/{id}/refresh` (из T05) запускает задание немедленно
- [ ] Рестарт воркера: lock не даёт параллельных дублей; пропущенный цикл «догоняется»
- [ ] Метрики сбора пишутся (число запросов/ошибок/длительность по источнику)
- [ ] Нет пути, по которому API вызывает внешний источник синхронно
- [ ] Тесты: порядок приоритетов, backoff, рестарт-без-дублей (интеграция с БД/ин-мемори)

## Швы для тестов
