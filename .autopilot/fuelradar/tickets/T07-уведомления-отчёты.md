# 07 — Уведомления, правила, пользовательские отчёты

**Требования:** R34, R35, R36, R37, R38, R39, R40, R76, R97i, A03
**Blocked by:** 04, 05
**Зона:** `backend/app/alerts/`, `backend/app/reports/`
**Волна:** 6
**Status:** ready

## Что должно заработать

События из diff состояния (FUEL_APPEARED, FUEL_DISAPPEARED, FUEL_LOW, QUEUE_INCREASED,
QUEUE_DECREASED, CONFIDENCE_INCREASED, STATION_NEW); правила уведомлений с условиями
Fuel/Distance/Status/Confidence/Queue (CRUD — свои endpoints в этой зоне); оценка правил
по новому состоянию; дедупликация: без изменения состояния — повторно не шлём (R37),
событие от трёх источников за 5 минут — одно уведомление (R38). Каналы: in-app лента +
счётчик (A03) — всегда; Web Push (VAPID) и Telegram — активируются ключами из .env, без
ключей помечены «не настроены» (R97i). Отчёты: `POST /reports` — топливо по видам
(есть/нет/заканчивается/не знаю) + очередь; GPS-вес < 300 м (R40); идемпотентность
(ключ клиента); отчёт → наблюдение → пересчёт confidence; админ-блокировка пользователя.
«Следить» из пустого состояния (R76) создаёт правило по текущим фильтрам.

## Из брифа, дословно

> «Сообщить, когда появится АИ-95 в радиусе 10 км» — Fuel, Distance, Status, Confidence, Queue → PUSH
> «FUEL_APPEARED, FUEL_DISAPPEARED, FUEL_LOW, QUEUE_INCREASED, QUEUE_DECREASED, CONFIDENCE_INCREASED, STATION_NEW»
> «Если состояние не изменилось: уведомление повторно не отправлять»
> «три источника в течение пяти минут сообщили об одном событии — пользователь должен получить одно уведомление»
> «distance_to_station < 300 m — достоверность повышается»

## Критерии приёмки

- [ ] E2E-сценарий §127 через API: правило «следить» → статус стал AVAILABLE → одно уведомление (в приложении)
- [ ] Смена AVAILABLE→AVAILABLE повторно не шлёт уведомление (R37)
- [ ] Три подтверждения одного события за 5 мин → одно уведомление (R38)
- [ ] CRUD правил + лимит активных правил на пользователя; у правила видны последнее событие и число срабатываний
- [ ] `POST /reports` сохраняет наблюдение, пересчитывает confidence, ведёт к событию при изменении статуса
- [ ] Повторная отправка того же отчёта (тот же idempotency-ключ) не дублирует наблюдение
- [ ] Отчёт с GPS < 300 м помечен «подтверждено на месте» и имеет повышенный вес (R40)
- [ ] Админ блокирует пользователя — новые сообщения не принимаются, история помечается
- [ ] Без VAPID/TG-ключей каналы «не настроены», in-app работает; с ключами — push/TG отправляются (юнит-тест с моком)
- [ ] Счётчик непрочитанных (A03): endpoint + сброс при прочтении
