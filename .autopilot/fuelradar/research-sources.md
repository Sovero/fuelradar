# Исследование источников данных — FuelRadar

Статус артефакта: **черновик-основа на 07.09.2026**. Даты и условия API меняются; перед
реализацией любого адаптера из списка `RESEARCH_REQUIRED` провести проверки из раздела
«Что проверить перед интеграцией» и зафиксировать результат в этом файле (новая строка
с датой проверки). Требование брифа: *«Никаких предположений агент не должен выдавать
за наличие API»* (R89).

## Статусы источников

| Статус | Смысл |
|---|---|
| `ACTIVE` | Включён в MVP. Доступ открытый/официальный, лицензия позволяет. |
| `RESEARCH_REQUIRED` | Нельзя строить критическую часть продукта, пока не проверено. Может стать активным после исследования. |
| `NOT_USED` | Сознательно не используется в MVP (не даёт оперативных данных или запрещён ToS). |

## Правила (из брифа §14)

Для каждого источника определяем: официальный API; лицензия/ToS; данные по видам топлива;
очереди; период обновления; rate limit; стоимость; требования к хранению; возможность
кэширования; запрет/разрешение автоматизации. Если оперативные данные доступны только
в интерфейсе и официального API нет — статус `RESEARCH_REQUIRED`.

## 1. OpenStreetMap / Overpass API — `ACTIVE`

- **Суть:** открытая карта мира; точки `amenity=fuel` — перечень физических АЗС, адреса,
  бренды (в т.ч. `brand:wikidata`), номер станции в `ref`, режим работы, телефон, цены
  (тег `fuel:price:*` — редкий и нерегулярный), наличие видов топлива (`fuel:diesel` и т.п.).
- **Официальный API:** да. Overpass API — официальный публичный интерфейс к данным OSM
  (`https://overpass-api.de/api/interpreter`, зеркала). Каталог можно получить и через
  Planet/региональные выгрузки, но для региона пилота достаточно Overpass-запроса по bbox.
- **Лицензия:** ODbL. Атрибуция: «© OpenStreetMap contributors». Обязательна на карте и
  при показе данных OSM. Совместимо с продуктом при соблюдении атрибуции.
- **Топливо по видам:** частично (теги `fuel:*`); это **Discovery**, а не оперативный
  Availability — теги описывают ассортимент, а не наличие сейчас.
- **Очереди:** нет.
- **Период обновления:** сами данные обновляются сообществом постоянно; перечень АЗС
  меняется медленно → достаточно сверки каталога 1 раз в 24 ч и по требованию.
- **Rate limit:** публичные Overpass-серверы просят не чаще ~1 запроса в несколько секунд
  и ограничивают размер ответа. Соблюдать; на большие регионы использовать ночные окна
  или собственный зеркальный сервер.
- **Стоимость:** бесплатно (публичные зеркала); платный self-host при больших объёмах.
- **Автоматизация:** разрешена публичной политикой Overpass при соблюдении fair use.
- **Вывод:** активный источник Discovery для MVP (R94i). Availability из OSM не берём.

## 2. Импорт официальных списков сетей (CSV/JSON, оператор) — `ACTIVE`

- **Суть:** ручной/полуручной импорт файлов, которые сети публикуют на сайтах
  («карта АЗС», «список станций», прайс-листы дилеров) или присылают по запросу.
- **Официальный API:** нет или не подтверждён — данные берём из опубликованных файлов.
  Формат и частота нестабильны → импорт через конвертер + ручное подтверждение администратором.
- **Лицензия:** проверяется для каждого файла отдельно; использовать только публично
  опубликованные данные с атрибуцией, никакого обхода ограничений.
- **Вывод:** активный источник для наполнения каталога сетей (Лукойл/Роснефть/Газпром…),
  помечается `source=network_import:<network>`.

## 3. Пользовательские сообщения — `ACTIVE`

- **Суть:** отчёты пользователей «топливо есть/нет», «очередь», «новая АЗС». Собственный
  канал данных (адаптер `UserReportAdapter`). Работает сразу, без внешних API.
- **Вывод:** активный источник Availability и очередей; участвует в Confidence с учётом
  репутации и GPS-подтверждения (R40, R41).

## 4. Яндекс Карты — `RESEARCH_REQUIRED`

- **Суть:** каталог АЗС, атрибуты, отзывы, в ряде случаев отметки о наличии топлива в UI.
- **Официальный API:** есть платные API (Geocoder, Search/Places). Но: (а) лицензия и ToS
  прямо запрещают строить конкурирующий сервис-агрегатор и хранить/кэшировать результаты
  поиска дольше оговорённого срока; (б) оперативного Availability в открытом API нет.
- **Что проверить:** актуальный текст ToS/лицензии; есть ли выгрузка «АЗС с топливом»;
  разрешено ли хранение и агрегация. **Вывод до проверки:** не использовать для Availability;
  для Discovery только при подтверждении лицензии. Без подтверждения — `RESEARCH_REQUIRED`
  и в MVP не подключается.

## 5. 2ГИС — `RESEARCH_REQUIRED`

- **Суть:** каталог организаций (АЗС — отдельная категория с атрибутами, в ряде городов —
  отметки о виде топлива и ценах в карточке).
- **Официальный API:** коммерческий (каталог/геокодер, ключи для разработчиков). Есть
  продуктовые ограничения на кэширование и объёмы.
- **Что проверить:** тарифы и ToS на хранение/агрегацию; доступность атрибутов топлива и
  цен по API; частота обновления. **Вывод до проверки:** кандидат в Discovery после
  исследования; в MVP не подключается.

## 6. Т-Банк (карты/гео) — `RESEARCH_REQUIRED`

- **Суть:** справочник организаций в приложении/на карте банка.
- **Что проверить:** существует ли публичный гео-API для сторонних разработчиков, какие
  условия. **Вывод до проверки:** в MVP не подключается.

## 7. Сети АЗС (Лукойл, Роснефть, Газпром, Газпромнефть, …) — `RESEARCH_REQUIRED`

- **Суть:** официальные списки станций и (в приложениях/сайтах некоторых сетей, напр.
  Газпромнефть) оперативные сведения о доступности топлива. Это самый ценный класс
  источников для Availability.
- **Что проверить по каждой сети отдельно:** публикует ли сеть машиночитаемый список
  станций (API или файл); отдаёт ли приложение/сайт сведения о наличии топлива по видам и
  можно ли их получать легально; есть ли ToS-запрет автоматизации; как часто обновляется.
  Результат — таблица по сетям с датой проверки.
- **Вывод до проверки:** каждая сеть — `RESEARCH_REQUIRED`. До наполнения сетевых
  адаптеров каталог сетей ведётся через импорт (раздел 2) и OSM.

## 8. Telegram-каналы/чаты о топливе — `RESEARCH_REQUIRED`

- **Суть:** водительские чаты, каналы «где есть бензин». Источник пользовательских
  сигналов, но: неструктурированный текст, спам, недостоверность.
- **Что проверить:** права на использование переписки; методы разбора. **Вывод до
  проверки:** в MVP не подключается; архитектура адаптеров позволяет добавить позже.

## 9. Сервисы цен на топливо (benzinpreis-аналоги, ценовые агрегаторы) — `NOT_USED`

- **Суть:** цены и наличие. Либо нет покрытия по Краснодару, либо лицензия запрещает
  переиспользование. В MVP цены — поле в наблюдениях без активного источника (R78 deferred).

## Что проверить перед интеграцией (чек-лист для `RESEARCH_REQUIRED`)

1. Существует ли официальный API/выгрузка (ссылка, дата проверки).
2. Разрешает ли лицензия/ToS: хранение, агрегацию, кэширование, автоматизацию.
3. Есть ли данные по конкретным видам топлива и очереди.
4. Период обновления и rate limit.
5. Стоимость (бесплатный тариф / коммерческий).
6. Требования к атрибуции и хранению raw-данных.

Результат проверки заносится в этот файл строкой вида `Проверено: <дата>, <источник>, <вывод>`,
после чего источник может сменить статус. **Ни один источник не меняет статус без такой строки.**
