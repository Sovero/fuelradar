# 03 — Нормализация и дедупликация мастер-каталога

**Требования:** R02, R09, R10, R13
**Blocked by:** 02
**Зона:** `backend/app/normalization/`, `backend/app/dedup/`
**Волна:** 3
**Status:** ready

## Что должно заработать

Из source_records — **мастер-каталог станций** с собственными `fr_station_*` ID.
Нормализация: названия/бренды («Лукойл», «ЛУКОЙЛ», «АЗС Лукойл №47», «Lukoil» → один
канон), топливо («95», «АИ-95», «AI95», «95 Экто» → base AI_95 + commercial ЭКТО).
Дедупликация — weighted compare (координаты 50%, бренд 20%, адрес 15%, название 10%,
телефон 5%): высокий порог → автослияние; средний → очередь подтверждения администратору;
вручную: объединить/разделить с журналом `dedup_decisions`. Идемпотентность: повторный
сбор находит ту же станцию по внешнему ID. Станция существует при подтверждении одним
источником (R02).

## Из брифа, дословно

> «Лукойл / ЛУКОЙЛ / АЗС Лукойл №47 / Lukoil / АЗС №47 … Система должна определить, что это одна станция»
> «coordinates = 50%, brand = 20%, address = 15%, name = 10%, phone = 5%»
> «При достаточно высокой вероятности записи объединяются автоматически. При средней — требуется подтверждения администратора»
> «base_fuel = AI_95, commercial_name = ЭКТО»

## Разделы спецификации

Истории §5 №1–5, §7 №1–8, §3 №1/4/6/8.

## Критерии приёмки

- [ ] «Лукойл»/«ЛУКОЙЛ»/«АЗС Лукойл №47» из разных источников на одной точке → одна master-станция с общими внешними ID
- [ ] Две станции одного бренда дальше порога расстояния не сливаются
- [ ] Пороги auto_merge/needs_review — конфигурация (§18); кандидаты «на подтверждение» видны админу
- [ ] Админ-действия «объединить» / «разделить» работают и пишут dedup_decisions (с разбором по весам)
- [ ] Повторный сбор не задваивает станции (идемпотентность по внешнему ID)
- [ ] Нормализация топлива: «95 Экто» → AI_95 + ЭКТО; неизвестное название → UNKNOWN, не ошибка конвейера
- [ ] Разделение ошибочно объединённых станций восстанавливает обе с прежними внешними ID
- [ ] Unit-тесты: normalize_fuel, compare (веса), идемпотентность, merge/split

## Швы для тестов

Чистые функции `normalization.normalize_fuel`, `dedup.compare` — unit без БД; публичный
метод модуля dedup — интеграция с БД (SQLite-dev).
