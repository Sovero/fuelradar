## Что должно заработать

Конвейер «источник → нормализация записей → source_records» с адаптерной архитектурой.
Активные адаптеры MVP: **OSM/Overpass** (Discovery: `amenity=fuel` по bbox/городу,
с атрибуцией ODbL «© OpenStreetMap contributors»), **импорт CSV/JSON** официальных
списков сетей (оператор/админ), **user_reports** (структура-адаптер для будущих отчётов).
Классы Яндекс/2ГИС/сети/Т-Банк/Telegram — заглушки со статусом RESEARCH_REQUIRED без
сетевого кода (исследование — `research-sources.md`). CLI `seed --region krasnodar`
(A01) наполняет каталог одним запуском. Каждый адаптер: `discoverStations`,
`getStationDetails`, `getFuelAvailability`, `getQueueStatus`, `healthCheck`.
Сбой одного источника изолирован (R84): не удаляет данные, пишет collection_jobs/logs,
не роняет сбор остальных.

## Критерии приёмки

- [ ] `seed` наполняет source_records по региону из OSM (офлайн-режим — по фикстуре) и из импортированного CSV/JSON; выводит счётчики и ошибки
- [ ] У каждой записи: source_id, внешний ID (например `node/…`), нормализованные координаты, бренд/название как от источника; сырое не выбрасывается
- [ ] Адаптер OSM помечен discovery-only (availability не выдаёт)
- [ ] RESEARCH_REQUIRED-адаптеры помечены и не выполняют сетевых вызовов
- [ ] healthCheck возвращает ONLINE/DEGRADED/OFFLINE/RATE_LIMITED/AUTH_ERROR
- [ ] Сбой одного источника: остальные собирают, ошибка в collection_logs, старые данные не тронуты
- [ ] Атрибуция OSM сохраняется (поле/источник, видимое в карточке позже)
- [ ] Тесты: парсинг OSM-ответа (фикстура), импорт CSV/JSON, изоляция ошибок, health
